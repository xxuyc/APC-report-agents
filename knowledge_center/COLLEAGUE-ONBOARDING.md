# 飞书知识中心团队接入

## 当前连接模式

两个报告 Agent 统一通过飞书自建应用的 `bot` 身份访问“多项目知识中心”。应用令牌由 `lark-cli` 根据 App ID 和 App Secret 自动获取并续期，不依赖任何员工的个人扫码登录。

飞书侧的一次性配置包括：

- 应用已开通并发布 Base 记录读取、创建和更新权限。
- 应用已作为 `edit` 协作者加入目标 Base。
- Base 中保留 Agent 运行和知识变更审计记录。

上述配置不需要每位同事重复操作。

## 推荐部署：中心连接服务

正式多人使用时，建议把 `lark-cli` 和应用凭据部署在一台受控运行机或内部服务中：

```text
同事的 Codex / Agent
        -> 内部知识中心接口
        -> 中心化 lark-cli（bot）
        -> 飞书多项目知识中心 Base
```

这样 App Secret 只保存一份。同事不需要取得密钥，也不需要飞书 OAuth；权限、日志、升级和故障处理都在中心运行环境统一管理。

## 过渡方案：同事本机运行

在中心服务上线前，同事可以在自己的受控电脑运行：

1. 安装与项目验证版本一致的 `lark-cli`。
2. 由管理员通过公司密码管理器或设备密钥管理工具配置同一个自建应用；不得通过 Git、聊天或普通文档传递 App Secret。
3. 从 `feishu-connection.example.json` 复制成本机的 `feishu-connection.local.json`，填写 Base token 和七张表 ID，保持 `identity` 为 `bot`。
4. 运行只读连通性检查，再运行一条带唯一审计 ID 的测试写回。
5. 确认本地文件被 `.gitignore` 排除后再开始业务运行。

只使用 `bot` 身份时，同事不需要执行个人 `auth login`。只有需要以员工本人身份访问其个人云空间或代表本人操作时，才需要各自完成用户 OAuth。

## 入职、离职与密钥轮换

- 新同事：授予内部知识服务调用权限；不直接发放 App Secret。
- 离职同事：撤销内部服务访问权，无需修改 Base 数据。
- App Secret 泄露或人员范围变化：立即轮换密钥，并更新中心运行环境。
- Base 迁移或更换：更新非敏感连接配置，并重新授予应用资源权限。
- 应用权限范围变化：重新发布应用版本，并执行读、写、回读验收。

## 验收标准

- 运行身份为 `bot`。
- 能读取七张表。
- 能写入并回读审计记录。
- 中文内容逐字一致。
- 本地配置和凭据没有进入 Git。
- Agent 运行表能够记录目标项目、参考项目、知识快照和产物链接。
