# 人工审核意见分层规则

## 处理顺序

1. 提取批注、修订和正文改动，保留原文、锚点和来源文件。
2. 将意见分类为：通用质量规则、项目级参数、模板级样式、流程缺陷。
3. 项目事实与特殊偏好只写入项目配置或金标准；不能直接迁移到其他项目。
4. 至少两个不同项目验证一致的分析方法，才能提升为通用分析规则。安全边界、证据边界和防误导的图表规则可立即作为质量闸门。

## 本轮已确认的规则族

- 展示口径：大额处理水量可换算为万m³，原值和换算关系必须可追溯。
- 来源交代：开篇说明“根据哪座厂提供的何时段生产运营数据”。
- 文字精简：删除实现过程、重复限制和不能推动结论的泛化表述；相关事实合并。
- 不确定信息：正式正文不写未经确认的解释。关键输入以浅黄色“关键输入提醒”提示框呈现，其他事项进入待确认工作簿。
- 图表尺度：绝对量和比例默认零基线，禁止为了强调趋势任意压缩纵轴。
- 跨对象比较：默认关闭；只有用户或项目配置明确批准时启用。
- 成本输入：价格和费用是完整成本核算的关键输入，缺失时必须触发人工补充提醒。
- 建设需求：必须指向批准的系统方向并说明解决的运营问题；“补数据、再分析”只能作为提醒项，不能充当最终建设结论。

## 迁移边界

- 不迁移厂名、设计规模、负荷率、设备数量、价格、排放标准和项目特定系统范围。
- 不把单个项目出现的异常阈值提升为全局阈值。
- 不因金标准存在某个系统章节，就自动认为其他项目也需要该系统。
