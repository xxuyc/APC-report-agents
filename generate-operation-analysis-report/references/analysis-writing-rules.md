# 分析报告写作规则

- 直接陈述指标及年内变化，不使用“AI分析认为”。
- 开篇明确数据来源，优先写成“根据××厂提供的××期生产运营数据……”，避免使用“流水线提取”等实现细节。
- 处理水量等大数按项目配置换算为“万m³”，底层计算和追溯仍保留原始 m³。
- 同一主题的紧邻事实合并成段，删除不能推进结论的泛化评价和重复限制语。
- 每个系统按“数据事实—运营含义—建设需求边界”组织。
- 用“年内高位、年内低位、阶段性变化”，避免以单年数据断言长期季节性。
- 不写“稳定达标”，除非存在适用标准和足够粒度的合规数据。
- 不写“主要由、导致”等因果表述，除非有额外证据。
- 建设需求采用“证据—运营痛点—建议系统—作用边界”结构。正文必须指向项目配置批准的系统方向；补数据、核口径和现场复核属于关键输入提醒，不得替代建设需求结论。
- 没有批准依据时不得写节能百分比、设备数量或确定性改造范围。
- 成本结论必须写清纳入的费用类别。
- 正式正文普通段落只写已确认信息。数据缺口、口径冲突和无法验证的推断分流处理：关键输入进入醒目的“关键输入提醒”提示框，其余进入《待确认事项.xlsx》，不得混写成正式结论。
- 厂际比较默认关闭。只有 `report_preferences.allow_cross_plant_comparison=true` 或用户明确要求时，才比较不同污水厂的负荷、单耗或排名。
